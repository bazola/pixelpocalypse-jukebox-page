Scripting

No browser needed

Everything Generate and the editor do with a song can also be run from a shell, over HTTP, or by an AI assistant. Songs made this way show up in the editor's song list.

On this page

  1. Command line
  2. HTTP API
  3. MCP tools

Command line

The app doesn't need to be running. From the repository:

uv run python -m engine.cli generate "a deep funky groove in C minor" --quick
uv run python -m engine.cli generate --persona funk --seed 42 --takes 3
uv run python -m engine.cli generate --persona funk --mood dark --speed fast --shape quiet_middle   # no prompt: a fresh idea from the dials
uv run python -m engine.cli generate "lo-fi beats" --count 20 --quick        # an overnight batch, seeds n, n+1, ...
uv run python -m engine.cli generate --plan songs/<name>/plan.json --out songs/<name>_again   # no LLM call
uv run python -m engine.cli generate --remix <song> "make it a dub version"     # a new song, <song>_remix
uv run python -m engine.cli ensembles save --song <song> --title "my band"
uv run python -m engine.cli generate "a slow jam" --ensemble <name>
uv run python -m engine.cli revise <song> "make the chorus bigger" --accept
uv run python -m engine.cli render <song>
uv run python -m engine.cli master <song>
uv run python -m engine.cli critique <song>
uv run python -m engine.cli export <song>                  # into ~/Music/Super Music Sound/<Title> v<N>/
uv run python -m engine.cli list_sounds --role bass
uv run python -m engine.cli swap_sound <song> bass surrealistic_mg_1_plus/normal_bass
  • <song> is a song's name, its folder or its song.json.
  • --help on any command lists its options.
  • --json prints the reply as JSON: the song folder, the mix, stem, MIDI and credits paths, and what the critics said. Progress goes to stderr, so the JSON can be piped.
  • --plan composes and renders a saved plan without the LLM. --seed gives it other notes.
  • Persona ids: producer, dj, reggae, blues, guitar, funk, soul, jazz, techno, synthwave, chiptune, hiphop, film, ambient, disco, dnb.

HTTP API

While the app is running, the server's API is described at http://127.0.0.1:8000/docs. Generating is a job: start it, poll it, then fetch the mix. In Git Bash:

SMS=http://127.0.0.1:8000
job=$(curl -s -X POST $SMS/api/generate -H "Content-Type: application/json" \
  -d '{"prompt": "a deep funky groove in C minor", "quick": true}')
id=$(echo "$job" | sed 's/.*"id":"\([^"]*\)".*/\1/')
song=$(echo "$job" | sed 's/.*"song":"\([^"]*\)".*/\1/')
until curl -s $SMS/api/jobs/$id | grep -q '"status":"\(done\|error\)"'; do sleep 5; done
curl -s -o $song.mp3 "$SMS/api/songs/$song/mix.mp3?download=1"

MCP tools

uv run python -m engine.mcp is an MCP server over stdio. Its tools are the same commands, with the same names and arguments: generate (with remix and ensemble), revise, render, master, critique, export, list_sounds, ensembles and swap_sound. An AI assistant can then make and edit songs for you. The app doesn't need to be running.

Use the path of your own clone in place of C:/path/to/super-music-sound.

Claude Code

claude mcp add super-music-sound -- uv run --directory C:/path/to/super-music-sound python -m engine.mcp

A generate takes minutes, and it sends progress as it goes. If a client gives up on it, raise that client's tool timeout (in Claude Code, MCP_TOOL_TIMEOUT, in ms), or ask for quick: true.

Any other MCP client

Add the server to its JSON config (often under mcpServers):

{
  "mcpServers": {
    "super-music-sound": {
      "command": "uv",
      "args": ["run", "--directory", "C:/path/to/super-music-sound", "python", "-m", "engine.mcp"]
    }
  }
}
